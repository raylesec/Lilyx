RESUMO EXECUTIVO
----------------
Foi construído um painel web com 5 módulos (Dashboard, Code Security,
Security Findings, Pipeline Monitor e Histórico), tema escuro com
accento rosa neon, navegação lateral e 100% de dados simulados.
Stack mínima: React 18 + Vite 5, CSS puro, gráficos e ícones feitos à
mão. O build de produção foi verificado (51 módulos, ~56 KB gzip).


1. AMBIENTE E FERRAMENTAS
-------------------------
PASSO 1.1 — Localizar/confirmar o Node.js no Windows
  - Verificado: Node v24.20.0 instalado via winget em:
    C:\Users\rayle\AppData\Local\Microsoft\WinGet\Packages\OpenJS.NodeJS.LTS_Microsoft.Winget.Source_8wekyb3d8bbwe\node-v24.20.0-win-x64
  - PROBLEMA ENCONTRADO: o PATH do terminal não incluí essa pasta,
    então `node`/`npm` não eram reconhecidos.
  - SOLUÇÃO (por sessão): prefixar o PATH:
      $env:PATH = "<pasta do node>;" + $env:PATH
  - POR QUE ASSIM: evitar reconfigurar o PATH permanente sem
    necessidade; funciona em qualquer PowerShell novo e é reversível.

PASSO 1.2 — Bloqueio de política de execução do PowerShell
  - PROBLEMA: scripts .ps1 bloqueados (execution policy); `npm`
    direto falhava.
  - SOLUÇÃO: usar sempre `npm.cmd` / `npx.cmd`.
  - LÓGICA: contorna a policy sem alterar configurações globais.

  - Tabela completa com filtros COMBINÁVEIS: severidade, status,

  - LÓGICA: derivar (e nunca armazenar) o status evita a classe
